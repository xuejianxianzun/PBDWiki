## 抓取用户列表

<button id="crawlUserList" type="button" class="hasRippleAnimation settingsPanelActionBtn" data-btn-emphasis="primary" data-btn-intent="brand"><span data-xztext="_抓取用户列表">抓取用户列表</span><span class="ripple"></span></button>

如果你想批量抓取多个用户的作品，可以使用这个功能。

点击这个按钮之后，下载器会显示两个输入框，让你输入用户 ID 列表，以及从每个用户那里抓取多少个作品。然后下载器会对你输入的用户逐个抓取和下载。

**提示：**
- 这个功能是为一次性抓取多个用户而设计的。如果你只需要下载一个用户的作品，可以进入他的主页并开始抓取。
- 如果你需要设置一些筛选条件（如作品类型、收藏数量、时间范围、标签），请先进行设置，然后再开始抓取。
- 请确认在 [抓取完成后，自动开始下载](/zh-cn/设置-下载/下载行为?id=抓取完成后，自动开始下载) 里勾选了“快速下载任务”，否则下载器不会自动开始下载。
- 在执行过程中，不要在这个标签页里执行其他抓取任务。如果有需要，你可以打开新的 Pixiv 标签页进行浏览和下载。
- 在执行过程中，如果你不小心关闭了这个网页，可以重新进入该页面，并点击“抓取用户列表”按钮来恢复进度。
- 在执行过程中，如果你想放弃（终止）该任务，可以点击“停止抓取”按钮。该任务会立即终止，并且不能从中断处恢复。

**一个已知问题：**

页面刷新后，恢复的下载任务不会被识别。

这个问题的原因是：
- 页面刷新后，下载器会自动恢复未完成的下载任务；
- 但不会自动恢复“抓取用户列表”任务。

复现流程是这样的：
- 用户执行了“抓取用户列表”的任务。
- 在抓取完一个用户后，下载器会开始下载他的作品。
- 在下载途中刷新网页。
- 刷新网页之后，下载器会自动恢复未完成的下载任务。问题发生在这里，此时下载器并没有恢复“抓取用户列表”的状态，所以这次下载没有与“抓取用户列表”关联起来。所以当这次下载完成之后，“抓取用户列表”的进度不会增加。
- 如果之后用户恢复了未完成的“抓取用户列表”任务，下载器会从之前尚未处理完毕的用户开始执行，也就是前面说的“未完成的下载任务”所对应的用户。下载器会对这个用户重新抓取、下载一次。

这是功能设计导致的已知问题，不是 Bug：
未完成的“抓取用户列表”任务只能通过用户手动点击“抓取用户列表”按钮恢复。这是设计如此，因为如果打开首页就自动恢复的话，可能会干扰用户的操作。而且用户也可能确实不需要恢复之前未完成的“抓取用户列表”任务了，所以不自动恢复更稳妥。

## 导入作品 ID 列表

<button id="importIDList" type="button" class="hasRippleAnimation settingsPanelActionBtn" data-btn-emphasis="secondary" data-btn-intent="brand"><span data-xztext="_导入作品ID列表">导入作品 ID 列表</span><span class="ripple"></span></button>

点击这个按钮之后，你可以选择一个包含作品 ID 列表的 JSON 文件，让下载器抓取它们。

这个 JSON 文件的内容格式如下：

```json
[
  { "id": "142565679", "type": "illusts" },
  { "id": "24769308", "type": "novels" },
  { "id": "7671451", "type": "novelSeries" }
]
```

`id` 是作品的 ID，`type` 是作品类型，可以是 `illusts`、`novels` 或 `novelSeries`。

?> 这个 JSON 文件可以由 [获取作品 ID 列表后导出 ID 列表，并停止任务](/zh-cn/设置-筛选/执行策略?id=获取作品-id-列表后导出-id-列表，并停止任务) 功能生成。这两个功能就是为了配合使用的。不过你也可以自己创建这个 ID 列表，只要内容格式符合要求即可。
