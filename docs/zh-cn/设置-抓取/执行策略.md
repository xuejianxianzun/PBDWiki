如果你启用了该功能，那么下载器在抓取每个作品前会先检查它是否有下载记录，如果有就不抓取它。这样可以减少不必要的抓取，节约时间。这个功能也有助于增量更新，因为你可以只抓取没有下载过的作品。

另外，在合并系列小说时，启用该设置可以跳过有下载记录的小说，只合并系列里新增的小说。

**注意：** 
- 该功能依赖下载器保存的下载记录，所以不是完全准确的。如果你清除了下载器的下载记录，那么下载器会忘记它下载过哪些文件。如果你想详细了解下载器的下载记录，可以查看 [管理下载记录](/zh-cn/设置-更多-下载?id=管理下载记录) 里的说明。
- 该功能不会对系列小说生效，因为下载器没有保存系列小说的下载记录。
- 对于多图作品，只要你下载了它的第一张图片，下载器就会为它显示边框。但如果你没有下载第一张图片，而是下载了之后的图片，下载器不会为它显示边框。这是因为该功能只会查找第一张图片是否有下载记录。

## 减慢抓取速度

减慢抓取速度可以避免下载器在抓取时被 Pixiv 临时限制（查看 [什么是 429 错误](/zh-cn/常见问题?id=什么是-429-错误)），但是会增加抓取时间。

如果用户启用了这个设置，那么下载器在抓取时的并发请求数量会变成 1。在每个请求完成之后，等待一定时间（取决于间隔时间的值）再发送下一个请求，以降低抓取频率，避免触发 429 限制。

这个设置有 2 个子选项：

### 当作品数量超过指定数量时启用

当要抓取的作品数量超过这个数字时（默认是 `100`），下载器才会使用慢速抓取模式。

如果要抓取的作品数量小于这个数字，下载器就会快速抓取（没有间隔时间）。

### 间隔时间

当一个请求完成后，等待多长时间再发送下一个请求。单位是毫秒，默认值是 `1600`。

如果你每天只抓取几百个作品，默认的间隔时间通常是安全的。如果你经常触发 429 错误，或者经常抓取更多作品，可以增加间隔时间，例如 `2000`、`3000`。`4000` ms 几乎是绝对安全的，即使抓取超过一万个作品也没问题，但通常不需要使用这么大的间隔时间。

?> 间隔时间不仅会在抓取阶段生效，也会在需要发送大量请求的一些场景里生效。例如：批量添加收藏、获取关注的用户列表。

------------

**注意：**

这个设置并不能完全避免 429 错误。原因：

1. 它假设用户只在一个页面抓取，此时应该不会触发 429 错误。但如果用户在 2 个或 3 个页面里同时抓取，因为发送请求比较频繁，就依然可能会触发 429 错误。
2. 用户的一些正常操作也是会消耗额度的，例如打开作品页面、预览作品、收藏作品等，当额度用尽时就会触发 429 错误。所以在抓取时，如果用户进行了很多此类操作，也可能会导致触发 429 错误。

## 获取作品 ID 列表后导出 ID 列表，并停止任务

<div class="option settingsPanel_optionCard" data-no="31" data-pin-bound="true" style="display: flex;">
  <a href="/#/zh-cn/设置-抓取/执行策略?flag=31" target="_blank" class="has_tip settingNameStyle" data-xztip="_导出ID列表的说明" data-tip="此时只会运行抓取，不会开始下载。&lt;br&gt;并且会忽略大多数过滤条件。" data-bind-click="true">

    <span class="gray1"> ? </span>
  </a>
  <input type="checkbox" name="exportIDList" class="need_beautify checkbox_switch">

</div>

如果你想获取下载器抓取到的作品 ID 列表，并且不需要下载文件，就可以启用这个选项。

**导出时机：**

- 导出时机是在下载器获取了所有要抓取的作品 ID 之后。注意这不是“抓取完成后”，而是更早。

下载器的抓取阶段分为 2 个步骤：
1. 获取所有作品的 ID 列表。
2. 逐个获取作品的详细数据，检查过滤条件，保存符合条件的作品的数据。

导出时机是在步骤 1 之后，并且会停止任务，也就是不会执行步骤 2。

!> 由于导出时机比较早，此时没有应用过滤器，所以导出的作品 ID 里可能含有不符合过滤条件的作品。

**导出的内容：**

导出的作品 ID 列表会保存到一个 JSON 文件里。你可以自行处理该文件，不过从设计目的上，这是为了配合另一个功能使用的：首页的 [导入 ID 列表](/zh-cn/按钮-开始抓取/首页?id=导入-id-列表)按钮。
