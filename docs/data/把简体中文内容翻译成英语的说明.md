# 把简体中文翻译为英语

## 背景说明

这是一个浏览器扩展程序 [Powerful Pixiv Downloader](https://github.com/xuejianxianzun/PixivBatchDownloader) 的 wiki 文档。这个扩展程序是一个爬虫和下载器，用于从 Pixiv.net 这个网站下载插画、漫画、小说等内容。大多数用户在 PC 端的浏览器上使用它。它有很多设置项，还会显示日志和一些提示消息。
我使用 docsify 制作了这个文档。

设置项和按钮相关的页面、菜单、侧边栏由 `build` 构造系统从下载器仓库自动生成（中英两种语言一起生成），不需要逐字翻译。

## 术语表

- `作品`（指 pixiv 上的投稿）翻译为`work`。
- `插画`翻译为`illustration`。
- `漫画`翻译为`manga`。
- `小说`翻译为`novel`。
- `动图`（指 pixiv 上的逐帧动画）翻译为`Ugoira`。
- `图片`（对 pixiv 上的图片的统称）翻译为`image`。
- `简介`（指作品的介绍信息）翻译为`description`。
- `抓取`（让这个下载器爬取作品数据）翻译为`crawl`。不要翻译为 `scraping`。
- `收藏`（把作品添加到收藏夹，相当于书签）翻译为`bookmark`。
- `设定资料`翻译为`glossary`。
- `珍藏册`翻译为`collections`。
- `点击`翻译为`click`。因为这个下载器是为 PC 端网页设计的，所以`点击`指的是鼠标点击，而非点击屏幕的 tap。
- `下载记录`有两种情况。第一种情况：指这个扩展程序保存的自己的下载记录格式，此时应该翻译为`download record`。第二种情况：指浏览器的下载记录（通常语句里会提及“浏览器”），此时翻译为`download history`。
- `发布时间`、`发表时间`、`投稿时间`是相同的意思，应该翻译为`posting time`。
- `命名规则` 在不同语言里的对应翻译（这是按照翻译顺序保存的多语言数组）：['命名规则','命名規則','Naming rule','命名規則','명명 규칙','Правила названий',]
- `约稿` 在不同语言里的对应翻译（这是按照翻译顺序保存的多语言数组）：['约稿','約稿','Requests','リクエスト','리퀘스트','Запросы',]

对于未列出的术语和词语，可以参考 PPD 的语言文件里的已有用法：
- 本地路径：`C:\document\github\PixivBatchDownloader\src\ts\langText.ts`
- 如果本地路径不可用，可以读取在线仓库里的对应文件：`https://github.com/xuejianxianzun/PixivBatchDownloader/raw/refs/heads/master/src/ts/langText.ts`

## 中文文件与英语文件的对照表

你可以读取简体中文的导航目录 `docs/zh-cn/_sidebar.md` 和英语的导航目录 `docs/en/_sidebar.md` 并建立对照列表，里面的每个超链接都指向一个 markdown 文件，这些文件是一一对应的。

备注：
- `_sidebar.md` 里可能含有无效的链接（如 `[settingsMenu]`、`[buttonsMenu]` 这样的特殊标记），忽略它们。
- 不在 `_sidebar.md` 里的文件不需要翻译成英语，例如：`README.md`。

## 需要翻译的内容

需要翻译的文件范围是 `docs/template/` 里的 md 文件。每种语言里的 md 文件可以分为两种内容：
1. 说明文字：`docs/template/<语言>/desc/`里的 md 文件。文件名是设置项的编号或按钮的 id。
2. 其它页面：除了 desc 文件夹之外的其他 md 文件。

翻译完毕后，运行 `npm run build` 即可把内容应用到两种语言的文档里。

具体到每个文件里的内容，需要翻译的有：
- md 文件里的中文。
- 中文的引号如 `“` 和 `”` 都翻译成英语的引号 `"`。
- 使用单个反引号包裹的文字如 `小说`。额外情况是 `未分類`，它不需要翻译。

## 不需要翻译的内容

- 非中文文本（例如日文、英文或其他语言）不需要翻译，保持原样即可。
- 对于使用 3 个反引号包裹的代码块，不需要翻译，保持原样即可。
- md 里的 html 代码不需要翻译，保持原样即可。
- 如果文件类型不是 `.md` 文件，就不翻译这个文件。
- 链接标记 `[setting:数字编号]` 和 `[button:按钮id]` 不需要翻译，保持原样即可（构建时会自动展开为对应语言的名称和链接）。
- 如果一个 md 文件的开头有 `[fetch]` 这个特殊标记，那么在翻译到其他语言时，只需要把目标语言的 md 文件内容改为 `[fetch]` 标记即可，不需要翻译或附带其他内容。因为这个标记意味着在 build 时从下载器里获取对应的文字，所以不需要在 wiki 里翻译。 

## 翻译时需要区分不同语言的图片

在不同语言里，有些图片可能是通用的（图片的路径里含有 `publicImages`），但也有些图片在每种语言里都是不同的（图片的路径里含有 `images`）。

翻译时，不要替换不同语言里特有的图片。这是为了防止这种情况：中文特有的图片覆盖了英语里特有的图片，使英语文档里错误的显示了中文内容的图片。

## 如何翻译超链接

有些文件里有 markdown 的 `[]()` 格式的超链接，我在这里详细说明处理方式。

**前提**：现在指向设置项、按钮的链接都已经改成了标记形式（`[setting:数字编号]`、`[button:按钮id]`），它们由 build 自动展开为对应语言的名称和链接，所以**不需要翻译**。因此文件里剩下的 `[]()` 链接通常是这两种：

1. 指向**其它页面**（例如 `常见问题`、`安装/在线安装`、菜单文件等）。
2. 指向**其它页面里的某个标题**（链接里带 `?id=`）。

> 如果你遇到了指向设置项或按钮的 `[]()` 链接（路径里含有 `设置-`、`按钮-`、`Settings-`、`Buttons-`），**不要自己翻译它**：这说明它还没有改成标记。请先告诉我，我会先把它改成标记，之后就不需要翻译了。

### 1. 替换语言路径

如果链接里含有 `zh-cn/`（简体中文的路径），把它替换为 `en/`。

### 2. 替换页面路径

普通页面的文件名在不同语言里是不一样的（中文页面叫 `常见问题.md`，英语页面叫 `FAQ.md`），对应关系见上文「中文文件与英语文件的对照表」（由两份 `_sidebar.md` 的链接顺序建立）。例如：

| 中文路径 | 英语路径 |
| --- | --- |
| `zh-cn/常见问题` | `en/FAQ` |
| `zh-cn/使用技巧` | `en/Usage-Tips` |
| `zh-cn/安装之后` | `en/AfterInstallation` |
| `zh-cn/安装/在线安装` | `en/Installation/OnlineInstallation` |

最可靠的办法是直接到 `docs/template/en/` 下看对应的文件夹和文件名。

### 3. 替换链接的名字

`[]` 里的文字就是链接显示的文本，直接翻译即可。

### 4. 替换标题锚点（`?id=`）

`?id=` 后面是目标页面里某个标题，作用是跳转到那个标题。

- 先在**英语的目标文件**里找到对应的标题。例如 `常见问题.md` 的「文件下载失败时会自动重试吗」对应 `FAQ.md` 的 `Will It Automatically Retry on Download Failure?`。
- 链接的**名字**用标题原文（保留大小写和空格）。
- 链接里的 `?id=` 要写成 **slug 形式**，因为 docsify 生成的锚点就是这种形式。处理规则：

  1. 全部转换为小写。
  2. 空格 ` ` 替换为横线 `-`。
  3. 单引号 `'` 替换为它的 ASCII 编号 `39`。
  4. 忽略这些半角标点（不产生对应的字符）：`(`、`)`、`,`、`.`、`?`、`!` 等。
  5. 其它符号原样保留；中文本身不受影响，原样写即可。

示例（普通页面）：

中文：

`[文件下载失败时会自动重试吗](zh-cn/常见问题?id=文件下载失败时会自动重试吗)`

英语：

`[Will It Automatically Retry on Download Failure?](/en/FAQ?id=will-it-automatically-retry-on-download-failure)`

示例（标题里带单引号）：`Don't download duplicate files` → `?id=don39t-download-duplicate-files`。

### 5. 标记里的 `?id=`

标记形如 `[setting:32?id=建立文件夹]`：编号（或按钮 id）保持不变，只需要把 `?id=` 后面的标题替换为英语里的对应标题**原文**——**不需要自己转成 slug**，build 会自动处理。

例如：

- `[setting:32?id=建立文件夹]` → `[setting:32?id=Creating Folders]`
- `[setting:32?id=使用命名标记排序]` → `[setting:32?id=Sorting with Naming Tags]`

英语标题可以这样查：

- 如果标题是**设置项/按钮的名称**：在 `docs/data/options_data.json`、`buttons_data.json` 里遍历 `names`，找到 `name["zh-cn"]` 与中文标题相同的项，`name.en` 就是英语文本。
- 如果标题是**说明文字里的小标题**（`### xxx`）：在 `docs/template/en/desc/<编号>.md` 里找对应的英语标题。

## 我可能使用不同的方式让你进行翻译

我可能会通过以下方式之一来让你进行翻译：

- **翻译文本片段**：如果我让你翻译一段文本内容，那么你应该把处理结果输出为 markdown 格式，用一个 markdown 代码区域展示。此时只在聊天消息里回复我即可，不需要把翻译结果保存到文件。
- **翻译指定文件**：我可能会让你翻译指定文件，此时需要翻译它的完整内容并保存到对应的英语文件里。
- **同步更改**：我可能会让你把中文 md 文件里做的修改同步到对应的英语 md 文件里。你需要从对应的英语 md 文件里删除被移除的内容（如果有），并把新增/有变化的内容翻译后添加到对应位置。注意：1. 在这种情况里，如果发生更改的文件不在前面列出的中文文件列表里，就不需要翻译它。2. 一个段落里可能只有部分文字被修改，但是在该模式里翻译时，应该翻译修改的内容所在的整段文字，而不是只翻译发生变化的部分文字。如果只翻译发生变化的部分文字，会导致这个段落的英语翻译存在错误。 3. 不需要翻译 html 代码。所以如果我修改了 html 代码，不需要修改英语文件里对应的 html 代码。

**注意：** 
- 在上述所有方式里，都需要遵循“需要翻译的内容”和“不需要翻译的内容”的要求。也就是说，即使我让你批量处理更改或者翻译指定文件，里面可能依然有些内容是不需要翻译的。
